_entorno.sh Libreria base. No se ejecuta: se carga con source. Mezcla .env (global, versionado) y .env.local (local, con las claves reales) y los exporta al entorno, aplicando la precedencia del proyecto. source scripts/_entorno.sh

firewall.sh Configura el firewall con iptables: solo la red local (192.168.1.0/24) entra a los puertos del servidor, y deja un servicio del sistema que restaura las reglas al arrancar. sudo bash scripts/firewall.sh aplicar

2. scripts/ — Para el equipo de desarrollo (Windows)

ScriptQue haceEjemplo
sync-vm.ps1 Vigila la carpeta del proyecto y copia a la maquina virtual los archivos que se modifican en Visual Studio Code (cada ~15 segundos). Normaliza los finales de linea a LF antes de copiarlos, porque el repositorio los exige asi. powershell -File scripts/sync-vm.ps1
sync-vm-vigilante.ps1 Revisa cada 60 segundos que el sincronizador siga vivo y lo vuelve a levantar si se cae (reinicio del equipo, suspension, cierre de sesion). Se arranca solo con la sesion de Windows
sync-vm-iniciar.ps1 Lanzador: si no hay ninguna instancia del sincronizador viva, arranca una. Pensado para las tareas programadas de Windows. powershell -File scripts/sync-vm-iniciar.ps1
Flujo de trabajo completo: se edita en VS Code → el sincronizador lleva el cambio a la VM (15 s) → el contenedor lo ve al instante porque el codigo esta montado en caliente → la web publica queda actualizada. La base de datos es una sola: la de la VM, a la que apuntan tanto el desarrollo de Windows como la web publicada.
